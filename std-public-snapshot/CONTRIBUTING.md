# Contributing to STD

Start with the [overview](docs/OVERVIEW.md), [results and scope](docs/RESULTS.md), and [snapshot notes](docs/SNAPSHOT.md).

For mathematical contributions, state the alphabets, source domain, cyclic/root convention, local rule, hypotheses, and exact claim. Separate proof, finite computation, conjecture, and erratum. Supply a decisive proof or counterexample with explicit limits.

For code contributions, include a reproducible command, exact input, expected result, and relevant boundary checks. Use exact arithmetic for certificates and explain unsupported cases and resource limits.

A reviewer who did not materially author the changed claim should assess it independently and disclose relevant contributions. Test success is execution evidence, not mathematical approval. Preserve valid unaffected reviews and re-review materially changed claims.

This snapshot has no configured collaboration endpoint or selected public-use license. A future public repository can establish its contribution process and licensing terms.
